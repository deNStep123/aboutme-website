# Текущее состояние сервера

## Базовая система

- Хост: `ub-26-den`
- ОС: Ubuntu 26.04.1 LTS (Resolute Raccoon)
- Часовой пояс: `Europe/Kyiv`.
- Служба времени: `chrony`; работа NTP и синхронизация времени подтверждены.
- `apt update` и `apt upgrade` завершились успешно.
- После обновлений сервер был перезагружен; контрольные проверки после перезагрузки прошли без ошибок, неуспешных systemd units нет.

## Сеть

Основной интерфейс `enp4s0` подключён и используется для default route. Его конфигурацию не меняли.

### Второй интерфейс enp2s0

Проведена только диагностика; конфигурация не менялась.

- Интерфейс физически отключён: `NO-CARRIER`, carrier off, в NetworkManager состояние `unavailable`.
- Активного соединения на интерфейсе нет.
- Сохранён профиль NetworkManager `Ethernet connection 1`, привязанный к `enp2s0`.
- В профиле включён autoconnect.
- IPv4: `192.168.1.246/24`; gateway: `192.168.1.1`.
- Линия принудительно настроена на `100 Mb/s`, full duplex; auto-negotiation выключен.

Пока кабель не подключён, профиль оставляем нетронутым и не активируем вручную. Его gateway потенциально способен добавить второй default route. Настройка резервного канала и failover отложена до восстановления физического подключения.

## Границы текущего этапа

На этом этапе не менялись пользователи, sudo-права, SSH, UFW/firewall, Netplan и настройки основного интерфейса. Это намеренно: сервер удалённый, поэтому любые потенциально нарушающие доступ изменения выполняются только отдельным контролируемым шагом.

## Отложенные технические задачи

- Перевести рабочую Netplan-конфигурацию с устаревшего `gateway4` на `routes:` в отдельное окно обслуживания.
- Вернуться к `enp2s0` только после физического подключения кабеля и решения, нужен ли ему LAN-доступ или настоящий failover.
